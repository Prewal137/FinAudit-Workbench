# Corrected Payload Reconciliation Report

This report compares the **original** synthetic JournalEntry payloads (see `reports/balanced_payload_summary.md`) with the **corrected** dry‑run payloads generated in `reports/corrected_payloads/`.

## Methodology

* Revenue and each expense category are taken directly from the workbook‑derived metrics – they are unchanged between the two versions.
* The original payloads used the Net Income balancing line with the **opposite posting direction** for loss months (Credit) and profit month (Debit).  This was identified as an accounting inconsistency.
* The corrected payloads (generated by `scripts/generate_corrected_payloads.py`) apply the **standard accounting rule**:
    * **Profit (Net Income ≥ 0)** → **Credit** to Retained Earnings (account 2).
    * **Loss   (Net Income < 0)** → **Debit**  to Retained Earnings (account 2).
* Because QuickBooks requires a JournalEntry to be **balanced (debits = credits)**, the corrected payloads add two **synthetic placeholder lines** on a custom account `9999` with the opposite posting type.  These lines do **not** belong to the workbook’s income‑statement categories and are intended solely for technical balance.
* All payloads are **dry‑run only** – no API writes were performed.

## Accounting Notes & Assumptions

1. **Balancing Account (`9999`)** – The placeholder account does not appear in the workbook’s chart of accounts mapping.  It must be created in the QuickBooks sandbox **before** any synthetic entries are posted (e.g., a custom “Synthetic Balancing” account of type *Other Current Liability*).  The account is **not** part of the income‑statement; therefore it does **not** affect the P&L figures derived from the revenue and expense lines.
2. **Effect on QuickBooks P&L** – The P&L in QuickBooks is computed solely from the *Revenue* (Credit) and *Expense* (Debit) lines.  The corrected Net‑Income posting (Credit for profit, Debit for loss) changes only the equity side and, because it is offset by the synthetic placeholder lines, the net effect on the P&L remains identical to the original workbook numbers.
3. **Synthetic vs. Real Accounting** – The Net‑Income line now follows proper accounting conventions, but the additional placeholder lines are **purely synthetic** to satisfy QuickBooks’ balanced‑entry requirement.  In a production scenario you would normally **omit** the placeholder lines and instead record a proper closing entry using an *Income Summary* account, but that would require a more complex multi‑step posting workflow beyond the current synthetic‑only proof‑of‑concept.
4. **Assumption** – The placeholder account `9999` will be created **once** in the sandbox and reused for all 18 periods.  Its presence does not interfere with existing financial reporting because it is excluded from the income‑statement mapping.

## Recommendations

*The corrected candidates are safe to submit for a **dry‑run** verification (they are balanced and respect standard Net‑Income posting direction).*

1. **Create the placeholder account** `9999` in the QuickBooks sandbox before posting any of the corrected JournalEntries.
2. **Post the corrected payloads** – each payload already includes the required synthetic balancing lines, so QuickBooks will accept them.
3. **Capture JournalEntry IDs** – after each POST, record the returned `Id` in a cleanup manifest (see `reports/cleanup_manifest_design.md`).
4. **After verification** you can delete the synthetic entries (including the placeholder lines) using the captured IDs.
5. **If you need a production‑grade closing entry**, replace the synthetic placeholder approach with a proper *Income Summary* workflow that consolidates revenue, expenses, and Net‑Income into equity without artificial balances.
